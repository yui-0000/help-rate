# 要件定義書: おらほの助っ人けっぱれーと

## 1. アプリの概要

* **アプリ名:** おらほの助っ人けっぱれーと
* **概要:** 高齢者や人手不足に悩む地域住民の困りごとを、身近な人が代わりに投稿し、地域の助っ人が閲覧・応募（手伝い）できるマッチングアプリ。
* **技術スタック:** Python, Flask, Peewee, SQLite

## 2. 想定ユーザー

* **代理投稿者 / 依頼者:** 高齢者の代わりにスマホやパソコンから困りごとを投稿する近所の人や親戚。
* **助っ人（手伝う人）:** アプリにアクセスし、地域の困りごとを見て手伝いを申し出る人。

## 3. 必須機能（Day8のデモで見せる3つの機能）

1. **お手伝い案件の投稿機能**
* タイトル、困りごとの種類（雪かき・買い物など）、詳しい内容、お礼・見返り、投稿者名を入力してデータベースに保存できる。


2. **案件の一覧表示・閲覧機能**
* データベースに保存されている困りごと案件をWebブラウザの画面に一覧でリスト表示する。


3. **簡易ユーザー管理機能**
* 投稿や閲覧の際に、操作している人の名前や立場（代理の人、助っ人など）を画面上で把握・切り替えできるようにする。



## 4. 余裕があれば追加する機能（時間が余ったら実装）

1. **案件の詳細画面と完了・編集機能**
* 案件の個別ページを表示し、内容の編集や完了状態へのステータス変更を行う。


2. **AIや外部APIの連携機能**
* LINE通知や自動マッチングなど、外部サービスとの連動。



## 5. 非機能要件

* **開発規模:** 14時間程度の制作時間を想定した最小限の構成（MVP）。
* **データ永続化:** Flaskを再起動してもデータが消えないよう、PeeweeとSQLite（`help_rate.db`）を用いてローカル保存する。
* **画面構成:** シンプルなHTMLテンプレート（一覧、投稿、詳細の3画面）で構成する。

## 6. 実装時に注意すべきこと

* **機能を欲張らない:** 複雑な自動マッチングやメッセージ機能は実装せず、まずは「投稿して一覧で見られる・応募できる（先着順）」のシンプルな形を最優先にする。
* **ファイルの階層を守る:** Flaskのお作法通り、HTMLテンプレートは専用の `templates` フォルダ内に配置する。
